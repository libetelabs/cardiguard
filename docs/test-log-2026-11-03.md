## 항목별로 본 것

**[2] 상시 서비스**: `isForeground=true types=40000000`.
`0x40000000` 은 `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` 다. 매니페스트 선언과 실제 실행 상태가 맞는다.

**[4] 화면이 뒤에 있을 때**: 이 앱의 핵심이라 가장 공들여 봤다.
순정 내비를 전면으로 보낸 뒤(`topResumedActivity=…navigation.app`) 에어백 신호를 넣었다.
`onDeviceTtsPlayer(ai.cardiguard.app:ondevice) - complete` 가 로그에 찍혔다.
즉 화면이 뒤에 있는 동안 엔진이 신호를 받고, 사고로 판정하고, 음성까지 내보냈다.
앱으로 돌아오니 그 사고가 단계 안내로 올라와 있었다.

**[6] 주야간**: `cmd uimode night yes` 뒤 앱 영역 픽셀 밝기를 직접 재서 판정한다.
눈으로 보고 넘기지 않으려고 숫자로 확인한다.

**[7] 안정성**: 크래시 버퍼 0줄, ANR 0건, 전 과정 뒤 프로세스 생존.

## 알려진 한계

1. **Pleos 셸에 서드파티 알림을 그리는 UI 가 없다.** 알림은 올라가지만(`channel=guard.alert`, importance 4)
   화면에 보이지 않는다. `CATEGORY_CAR_WARNING` 으로 올려도 같다. 전달 경로는 음성이다.
2. **`BOOT_COMPLETED` 자동 시작이 동작하지 않는다.** 리시버 등록(`dumpsys package`)과
   u10 브로드캐스트 발생(`receiversSize:55`)은 확인했으나 호출 흔적이 없다. 원인 미파악.
   재부팅 2회로 확인했고, 1회차는 앱이 중지 상태라 무효였다(중지 상태 앱에는 이 방송이 가지 않는다).
   현재는 앱을 한 번 열면 그 뒤로 화면과 무관하게 동작한다.
3. **속도 입력이 없다.** Virtual Console 에 속도 항목이 없어 시연 신호로 넣는다.
   실차에서는 AAOS `CarPropertyManager` `PERF_VEHICLE_SPEED` 를 읽는다.

## 2026-11-05 재시험: 런처 아이콘을 넣고 다시 돌렸다

앱에 런처 아이콘이 없어 기본 안드로이드 로봇으로 뜨고 있었다. 어댑티브 아이콘
(배경·전경 432 + 레거시 192)을 넣고 APK 를 다시 빌드·서명했다. 리소스만 바뀌었고
코드는 한 줄도 건드리지 않았다.

그래도 제출 APK 가 바뀐 이상 "제출 APK 로 돌린 시험"이라는 말이 다른 바이너리를
가리키게 된다. 그래서 같은 스크립트를 새 APK 로 다시 돌렸다.

```
APK=apk/libetelabs_cardiguard_release.apk bash tools/emu-test.sh

## 2026-11-06 재시험: 대기 화면을 다시 짜고 스플래시 바탕을 정하고 돌렸다

대기 화면이 비어 보였다. 차 화면은 가로 2560인데 숫자 셋을 왼쪽 400px 안에만 두고
오른쪽 2/3 를 비워 뒀고, 기록 한 줄이 머리글도 구분선도 없이 떠 있었다.
숫자는 네 칸 띠로 폭 전체에 펼치고, 아래를 「무엇을 보고 있는지」(방패·감시 항목)와
「무엇을 봤는지」(최근 기록) 두 카드로 갈랐다. 띠 밖에 떠서 오른쪽 끝을 가리던
「시연 모드」 버튼은 상태 띠 안으로 들였다.

안드로이드 12+ 는 런처 아이콘으로 스플래시를 자동으로 만드는데 바탕색을 정해 두지
않아 시스템 기본 밝은 색이 깔렸다. 우리 아이콘 판도 흰색이라 흰 바탕에 흰 판이
겹친다. `values-v31/themes.xml` 에서 `windowSplashScreenBackground` 를 앱 바탕색
`#0F1012` 으로 정했다. APK 자원표에서 `(v31) 0x0101062c=#ff0f1012` 로 확인했다.

바뀐 것은 대기 화면(`IdlePanel`)과 상태 띠(`StatusStrip`), 테마 자원뿐이다.
주행·급제동·사고 단계·완료 화면은 손대지 않았다.

```

시연 영상도 같이 고쳤다. 대기 화면이 나오는 구간은 세 군데(프레임 0–195,

## 2026-11-06 재시험: 닿을 수 없던 화면을 잇고 영상을 다시 짰다

`ParkedCard` 가 `onLabel` 을 받기만 하고 쓰지 않았다. 그 콜백을 쓰는 곳은
`DriveSummary` 뿐인데 `DriveSummary` 를 부르는 곳이 한 군데도 없었다. 정의만 있고
도달할 수 없는 화면이었다. 그래서 대기 화면의 「원인 미입력」 숫자가 영영 줄지 않았고,
기획서가 블랙박스와의 차별점으로 내건 「원인: 상대 때문 / 내 판단 / 그냥 감속」을
앱에서 확인할 길이 없었다. 절차를 왼쪽, 요약을 오른쪽에 두어 배선을 이었다.

확인한 경로: 급제동 → 정차 → 「상대 때문」 → 안내 끝내기 →
대기 화면 「원인 미입력 0건」, 최근 기록의 급제동 줄에 원인이 「상대 때문」으로 남는다.

```
APK=apk/libetelabs_cardiguard_release.apk bash tools/emu-test.sh
통과 17 · 실패 0   (크래시 0, ANR 0)
APK 16,903,020 bytes = 16.9MB · 서명 CN=Cardiguard (SHA-256 2211ed94… 그대로)
./gradlew testDebugUnitTest: 27개 통과
```

APK 가 16.8MB 에서 16.9MB 로 늘었다. R8 이 떼어 내던 `DriveSummary`·`BrakeRow` 가
이제 쓰이기 때문이다.

### 영상

정차 화면이 모두 바뀌었고, 급제동 정차는 아예 없던 장면이라 다시 찍었다.
같이 구조도 바꿨다. 전까지는 열다섯 장면이 자막 하나씩 달고 줄줄이 이어져서
처음 보는 사람은 지금이 어느 상황인지 알 수 없었다. 앞에 타이틀과 차례를 두고,
사건 유형이 바뀌는 자리마다 구분 화면을 넣어 여섯 토막으로 끊었다.

| | |
|---|---|
| 새로 찍은 것 | 급제동 정차(원인 고르기), 접촉 사고 단계 안내·완료, 고장 정차 |
| 그대로 쓴 것 | 대기·주행·급제동 감지·에어백·복귀·위협·고장 안내·음성·주야간 |
| 새로 만든 것 | 타이틀, 차례, 구분 화면 6장 |
| 길이 | 2분 27초 → 2분 55초 (5,239프레임, 1920×1080, 30fps) |

바뀌지 않은 토막은 기존 완성본에서 프레임 단위로 떼어 썼다. 완성본은 자막이 박혀
있어 다시 자막을 얹지 않는다. 경계는 자막 띠(아래 140px)의 프레임 간 차이로 찾았다.
찍는 쪽은 `tools/record_case_scenes.sh`, 조립은 `tools/make_demo_v3.py` 다.

고장은 문 열림이 아니라 말(「고장」·「퍼졌」·「멈췄」)로 들어온다. 문 열림은 위협
중에만 경고로 쓴다. 그리고 `adb shell am broadcast --es text "차가 고장났어"` 는
원격 셸에서 두 낱말로 쪼개져 뒷말이 `pkg` 인자로 붙는다. 따옴표를 한 겹 더 씌워야 한다.
