## 1. 앱 한 줄 소개

카디가드는 운전 중 위험한 상황이 생기면 음성으로 대응 방법을 안내하고, 차량 신호와 운전자의 설명을 함께 기록하는 차량용 앱입니다.

## 2. 기획 배경

### 기획 계기

처음에는 끼어들기나 보복운전을 당했을 때 신고에 필요한 기록을 쉽게 남기는 앱을 생각했습니다. 운전 중에는 휴대폰을 꺼내기 어렵고, 나중에 블랙박스 영상을 찾으려 해도 정확히 언제 있었던 일인지 기억나지 않는 경우가 있기 때문입니다.

기획하면서 신고에 앞서 필요한 것이 있다고 봤습니다. 갑자기 끼어든 차 때문에 급제동하면 놀라거나 화가 나기 쉽습니다. 상대를 따라가거나 차에서 내려 따지기보다, 운전자가 진정하고 안전하게 대응할 수 있도록 돕는 일이 먼저였습니다.

그래서 카디가드는 위험한 순간에 짧은 음성 안내를 제공하고, 상황이 끝난 뒤에는 기록과 후속 절차를 확인하는 방향으로 구체화했습니다. 주행 중에는 운전에 집중하고, 안전하게 정차한 뒤 필요한 일을 처리하도록 돕는 것이 목표입니다.

### 주목한 불편

끼어들기로 급제동했을 때는 당시 시각과 위치를 기억하기 어렵습니다. 카디가드는 급제동을 감지하면 이 정보를 남기고, 정차 후 접촉 여부와 급제동 원인을 확인합니다. 자동으로 감지하지 못한 상황도 “저장해”라는 음성 명령으로 기록할 수 있습니다.

상대 차량이 따라붙거나 진로를 막는 상황에서는 어떻게 대응해야 할지 판단하기 어렵습니다. 반복된 급제동이 감지되면 위협을 받고 있는지 확인하고, 운전자의 답변에 따라 문 잠금 요청과 112 연결 안내로 이어집니다.

사고나 고장 직후에도 당황하면 필요한 조치를 놓칠 수 있습니다. 이때는 상황에 맞는 초기 행동을 음성으로 안내하고, 정차 후 사진 촬영, 연락처 확인, 보험 접수 등의 절차를 단계별로 보여 줍니다.

### 왜 지금 필요한가

경찰청 자료를 인용한 2026년 보도에 따르면, 보복운전으로 검찰에 송치된 사건은 2022년 1,570건, 2023년 1,705건, 2024년 1,717건, 2025년 1,726건으로 3년 연속 증가했습니다. 2026년 상반기에도 931건이 송치됐습니다. 같은 자료에서 4년 6개월간 누적 7,649건 중 면허가 취소된 경우는 7건(0.09%)으로 집계됐습니다. 이러한 현황에서 카디가드는 위협을 겪는 운전자가 현장에서 안전하게 대응하고 당시 상황을 남길 수 있도록 돕고자 합니다. (출처: 경찰청 자료 인용 보도, 2026)

사고 이후의 분쟁에 대비할 필요도 있습니다. 보험연구원은 국내 자동차사고 과실비율 분쟁이 일본과 달리 지속적으로 증가하고 있다고 진단했습니다. 카디가드는 블랙박스 영상에 더해 당시 차량 신호와 운전자의 설명을 함께 남겨, 이후 상황을 확인하는 데 참고할 수 있도록 합니다. (출처: 보험연구원 연구보고서 2026-06)

### 2차 사고 통계와 안내 설계

한국도로공사 집계에서 고속도로 2차 사고의 치사율은 48.3%입니다. 최근 5년간 고속도로 사망자 784명 중 138명, 약 18%가 2차 사고로 숨졌으며, 2차 사고 사망자의 74%는 차량 안이나 차량 주변에 머물다 사고를 당했습니다. 이 수치는 고속도로 사고·고장 후 차량 안이나 주변에 계속 머무는 위험을 보여 줍니다. (출처: 한국도로공사 집계)

카디가드가 위협과 고장에 서로 다른 행동을 안내하는 이유입니다. 상대 운전자의 위협에는 차에서 내려 직접 대면하지 않도록 “차 안에 머무르세요”라고 안내하고, 고속도로 고장에는 2차 사고를 피하도록 “가드레일 밖 안전한 곳으로 대피하세요”라고 안내합니다. 위협 상황의 문 잠금 요청과 사고·고장 상황의 대피 안내를 구분한 것도 같은 이유입니다. 차량 화재나 후속 충돌 위험이 있는 경우까지 차 안에 머무르도록 일괄 안내하지 않도록, 실제 안내는 현장 위험과 대피 가능 여부를 함께 고려해야 합니다.

따라서 급제동만으로 상황을 단정하지 않고 차량 신호와 운전자의 답변을 함께 사용합니다. 무엇이 일어났는지를 기록하는 것뿐 아니라, 그 상황에서 어떤 행동을 먼저 해야 하는지 구분해 안내하는 것이 카디가드의 핵심입니다.

또한 급제동 횟수만으로는 당시 상황을 충분히 설명하기 어렵습니다. 앞차의 갑작스러운 끼어들기를 피한 것인지, 운전자 본인의 판단이 늦었던 것인지 구분되지 않기 때문입니다. 카디가드는 정차 후 운전자가 원인을 남길 수 있게 해, 나중에 주행 기록이나 블랙박스 영상을 확인할 때 참고하도록 합니다.

## 3. 주요 기능 및 차량 특화 요소

### 주행 기록과 상황별 대응

평상시에는 주행 시간, 거리, 급제동 횟수를 기록합니다. 기어가 P로 전환되면 이번 주행의 요약을 보여 주고, 각 급제동의 원인을 확인합니다.

급제동, 위협, 사고, 고장 상황에서는 짧은 음성 안내를 제공합니다. 주행 중에는 설명을 길게 이어가지 않고, 상세한 후속 절차는 정차 후 확인하도록 구성했습니다.

### 급제동 원인 기록

정차 후 운전자는 각 급제동에 대해 “상대 때문 / 내 판단 / 그냥 감속” 중 하나를 선택합니다. 주행 중 위협 여부를 묻는 질문에 “네”라고 답한 경우에는 해당 주행의 급제동에 위협 응답을 자동으로 남깁니다.

차량에서 수집한 속도·브레이크·기어 정보와 운전자가 선택한 원인을 함께 보관합니다. 운전자의 답변은 당시 상황에 대한 본인의 설명이며, 객관적으로 확인된 원인이나 과실 판정을 뜻하지 않습니다.

### 기존 서비스와의 차이

블랙박스 영상과 운전 점수는 각각 사고 장면과 주행 습관을 확인하는 데 도움이 됩니다. 카디가드는 여기에 운전자가 당시 어떤 상황을 겪었는지 설명할 수 있는 기록을 더하려고 합니다.

예를 들어 급제동 시각에 “상대 때문”이라는 응답이 남아 있으면, 이후 해당 시점의 영상을 찾아 상황을 확인할 수 있습니다. 영상 자체를 대신하거나 앱이 과실을 판단하는 방식은 아닙니다.

기록뿐 아니라 현장에서의 대응도 돕습니다. 차량 신호로 이상 상황을 감지하고, 음성으로 초기 행동을 안내한 뒤 정차 후 절차로 연결합니다. 감지부터 기록, 후속 안내까지 차량 안에서 이어지는 흐름을 만드는 데 중점을 뒀습니다.

### 차량 신호 활용

- 차량 속도와 브레이크 페달: 속도 변화와 실제 제동 여부를 함께 확인해 급제동을 감지합니다.
- 기어 D/P: 주행 세션의 시작과 종료를 구분하고, 상세 절차는 P 상태에서 표시합니다.
- 도어 잠금과 위치: 위협 상황에서 잠금을 요청하고 결과를 확인합니다. 문이 열리면 내리기 전 주변 안전을 확인하도록 안내합니다.
- 에어백 전개: 전개 신호가 들어오면 사고 대응으로 전환합니다. 에어백이 전개되지 않는 사고까지 모두 감지하는 것은 아닙니다.
- 차량 음성 기능: 화면을 조작하지 않고 안내를 듣거나 짧게 답할 수 있도록 TTS와 STT를 사용합니다.
- 백그라운드 감지: 내비게이션이나 음악 화면을 사용 중일 때도 차량 신호를 받아 음성 안내와 알림을 제공합니다.
- 주야간 설정: 차량의 uiMode에 따라 화면을 전환해 낮과 밤의 시인성을 확보합니다.
### 운전 중 사용 원칙

주행 화면에는 짧은 안내와 큰 버튼만 표시합니다. 사고가 감지돼도 다른 앱의 화면을 강제로 가리지 않으며, 음성 안내와 알림을 통해 상황을 알립니다.

문 잠금 요청은 위협 상황에만 사용합니다. 사고 대응에서는 앱이 문을 잠그지 않습니다. 112 연결도 자동 발신하지 않고 운전자가 전화 화면에서 직접 실행하도록 합니다.

음성 안내는 사전에 작성한 문구를 사용합니다. 음성 인식에 실패하면 한 번만 다시 묻고, 같은 질문을 계속 반복하지 않습니다.

정차 후 절차는 한 화면에 한 단계씩 보여 줍니다. 운전자가 “했어요 / 해당 없음”으로 처리하면 그 결과를 기록해, 어디까지 진행했는지 확인할 수 있습니다.

## 4. 주요 사용 시나리오

### 평소 출퇴근

기어를 D로 전환하면 주행 감시를 시작합니다. 도착 후 P로 전환하면 주행 거리, 시간, 급제동 횟수를 보여 줍니다. 급제동이 두 번 있었다면 각 기록을 보고 “상대 때문” 또는 “그냥 감속” 등 원인을 선택합니다.

### 끼어들기로 급제동한 경우

급제동이 감지되면 시각과 위치를 저장하고 “괜찮으세요? 시각과 위치를 기록해뒀어요. 따라가지 마세요.”라고 안내합니다. 정차 후에는 접촉 여부를 확인하고, 사고가 아니라면 블랙박스 영상 보관을 안내합니다.

### 상대 차량이 위협하는 경우

급제동이 반복되면 “누가 위협하고 있나요?”라고 묻습니다. 운전자가 “네”라고 답하면 문 잠금을 요청하고 112 연결 의사를 확인합니다. 정차 후에는 위협 대응 절차를 4단계로 보여 줍니다.

### 에어백이 전개된 사고

에어백 전개 신호를 받으면 사고 대응을 시작합니다. 앱은 문을 잠그지 않으며, 부상자가 있는 경우 119 연락을 우선 안내합니다. 정차 후에는 사진 촬영, 연락처 확인, 보험 접수 등을 포함한 7단계 절차를 제공합니다.

### 자동 감지가 어려운 상황

정체 구간의 끼어들기처럼 급제동으로 잡히지 않는 상황에서는 “저장해”라고 말해 시각과 위치를 남깁니다. 정차 후 해당 시점의 블랙박스 영상을 보관하고 제보할지 판단할 수 있습니다.

### 고속도로에서 차량이 고장 난 경우

“차가 고장났어”라고 말하면 비상등 작동, 안전한 곳으로 대피, 긴급출동 연락 순서로 안내합니다. 위협 대응과 구분해 2차 사고를 피하는 데 필요한 행동을 우선합니다.

## 5. 개발 계획

### 구현 방식

Pleos Connect(AAOS) 환경에서 Kotlin과 Jetpack Compose로 개발하고 있습니다.

- domain — 순수 Kotlin. 급제동 감지, 상황 판단 상태 기계, 음성 의도 해석, 안내 문구집.
차량 없이 실행할 수 있는 단위 테스트 27개를 구성했습니다.

- car — Pleos SDK와 AAOS 연동. 연동에 실패하면 앱을 종료하지 않고 화면에 오류 상태를 표시합니다
- core / service — 화면이 닫혀도 엔진과 차량 연결을 유지하도록 프로세스 단위로 관리합니다.
포그라운드 서비스(specialUse)에서 감지를 계속 수행합니다

- ui — 주행 화면(도로 그래픽 + 한 문장), 정차 화면(한 화면에 한 단계씩 넘기는 안내와 주행 요약).
검정·흰색·빨강을 사용하고, 위험 수준에 따라 빨강의 표시 면적을 달리합니다. 주야간은 차량 설정을 따릅니다

### SDK와 API 사용 계획

- SDK / API: Vehicle / 쓰는 기능: 기어 선택 상태 / 카디가드에서의 역할: 주행 세션 시작·종료, 주행/정차 화면 전환
- SDK / API: Vehicle / 쓰는 기능: 브레이크 페달 상태 / 카디가드에서의 역할: 급제동 판정 조건
- SDK / API: Vehicle / 쓰는 기능: 도어 위치 / 카디가드에서의 역할: 위협 중 문 열림 경고
- SDK / API: Vehicle / 쓰는 기능: 도어 잠금 지원 구역 조회·잠금·상태 조회 / 카디가드에서의 역할: 위협 시 잠금 요청과 결과 확인
- SDK / API: Vehicle / 쓰는 기능: 좌석 에어백 전개 / 카디가드에서의 역할: 에어백 전개 시 사고 대응 전환
- SDK / API: TextToSpeech (온디바이스) / 쓰는 기능: 한국어 음성 안내 / 카디가드에서의 역할: 주행 중 한 문장 안내
- SDK / API: SpeechToText (온디바이스) / 쓰는 기능: 한국어 음성 인식 / 카디가드에서의 역할: "도와줘", "저장해", "네/아니요"
- SDK / API: FusedLocation / 쓰는 기능: 현재 위치, 마지막 위치 / 카디가드에서의 역할: 기록에 위치 남기기
- SDK / API: AAOS CarPropertyManager / 쓰는 기능: PERF_VEHICLE_SPEED / 카디가드에서의 역할: 급제동 감지와 주행 거리. 현재 구현에서는 AAOS 표준 API로 속도 값을 읽습니다
### 개발 범위와 현재 상태

- 범위: 급제동 감지, 위협 승급, 충돌 대응, 고장·기록 음성 명령 / 상태: 구현. 에뮬레이터 release 빌드에서 동작
- 범위: 주행 세션, 급제동별 기록, 정차 후 원인 표시, 위협 답변 자동 저장 / 상태: 구현
- 범위: 온디바이스 음성 안내 / 상태: 구현. 에뮬레이터에서 재생 확인
- 범위: 음성 인식 / 상태: 구현. 인식 경로는 확인, 실제 목소리 정확도는 시험 중
- 범위: 문 잠금 / 상태: 지원 구역 조회 후 잠금 요청 성공, 잠김 상태 확인. 에뮬레이터 문이 처음부터 잠김이라 잠금 전환 장면은 미확인
- 범위: 에어백 / 상태: 코드 구현. 이 에뮬레이터는 에어백 신호를 지원하지 않아 시험 입력으로 검증했다
- 범위: 속도 / 상태: Virtual Console에 속도 입력이 없어 시연 모드로 넣는다. 시연 모드는 에뮬레이터에서만 사용할 수 있습니다
- 범위: 화면이 뒤에 있을 때의 감지 / 상태: 구현. 순정 내비를 전면에 둔 채 에어백 시험 신호 입력 → 엔진이 사고로 판정하고 음성 안내가 실행되는 것을 로그로 확인
- 범위: 정차 후 단계 안내 / 상태: 구현. 한 화면에 한 단계, 「했어요 / 해당 없음」으로 처리를 남기고 끝에 처리 건수를 보여 준다
- 범위: 주야간 자동 전환 / 상태: 구현. 차량 uiMode를 따릅니다
- 범위: 자동 스모크 시험 / 상태: 구현. 제출 APK 로 17항목 통과·0 실패(크래시 0, ANR 0)
- 범위: 사건 내보내기(텍스트·JSON 요약) / 상태: 2차 PT 전 구현 예정
- 범위: 주행 점수(급제동·급가속·과속, 운전자 원인 응답을 반영하는 앱 내부 점수) / 상태: 2차 PT 전 구현 예정

## 6. 기대효과 및 발전 가능성

### 주요 사용자와 기대효과

주요 사용자는 출퇴근이나 업무로 매일 운전하는 사람입니다. 평소에는 주행 요약과 급제동 기록을 확인하고, 위험한 상황이 생겼을 때는 음성 안내와 후속 절차를 이용합니다. 특히 야간·장거리 운전자와 초보 운전자에게 도움이 될 것으로 기대합니다.

운전자가 얻는 실질적인 이점은 당시 상황을 기억에만 의존하지 않아도 된다는 점입니다. 시각과 위치, 차량 신호, 본인의 설명을 함께 남겨 두면 이후 영상을 찾거나 상황을 설명하기 수월해집니다. 당황한 상태에서 필요한 조치를 하나씩 확인할 수 있다는 점도 중요합니다.

### 이용 규모 산정

도달 가능한 시장은 Pleos 탑재 차량을 기준으로 검토했습니다. 검토에 사용한 더 뉴 그랜저의 2026년 6~9월 판매량 33,423대와 디 올 뉴 아반떼의 9월 판매량 7,305대를 합하면 40,728대입니다. 구형 모델이 함께 판매된 5월 그랜저와 8월 아반떼는 제외했습니다. 출처는 현대자동차 월별 판매 실적이며, 제출 전 모델별 탑재 범위와 집계 기준을 확인할 예정입니다.

9월의 판매 속도가 이어진다는 가정으로 계산한 1년 뒤 규모는 약 235,000대입니다. 신형 투싼과 2027년 기아 탑재분은 포함하지 않았습니다. 이 수치는 앱의 이용자 수가 아니라 잠재적으로 접근 가능한 차량 규모입니다.

기본 탑재와 자동 실행이 가능하고, 대상 차량의 92%가 월 1회 이상 운행한다고 가정하면 월간 실행 차량 수는 현재 기준 약 37,000대, 1년 뒤 약 216,000대입니다. 다만 기본 탑재 여부, 사용 동의, 권한 허용, 기능 비활성화에 따라 실제 규모는 달라집니다. 92% 역시 실측치가 아닌 계산용 가정이므로 확정적인 MAU 전망으로 사용하지 않습니다.

### 사용성과 유지율 확인

자동으로 실행되는 앱에서는 실행 횟수만으로 사용자가 가치를 느끼는지 판단하기 어렵습니다. 월간 실행 차량 수와 별도로, 주행 요약을 확인한 사용자와 급제동 원인에 응답한 사용자를 집계할 계획입니다.

주요 지표는 급제동 원인 응답률, 상황별 안내 단계 처리율, 기능 비활성화율입니다. 필요하지 않은 안내가 자주 나오는지, 음성 인식이 반복해서 실패하는지도 함께 확인합니다.

D1 재방문 75~85%, D30 유지율 약 90%는 실측 근거가 없는 가정이므로 목표치로 확정하지 않았습니다. 초기 사용자 테스트에서 실제 사용 패턴을 확인한 뒤 유지율 목표를 정하겠습니다.

### 서비스 확대 계획

우선 주행 기록과 상황별 안내를 무료로 제공하고, 감지 정확도와 사용성을 개선할 계획입니다. 사건 요약 내보내기와 주행 점수는 2차 PT 전 구현을 목표로 합니다.

보험 연계는 후속 검토 과제입니다. 차량 신호에 급제동 원인 응답을 더하면 운전 습관을 해석하는 데 참고할 수 있습니다. 다만 “상대 때문”이라는 응답만으로 감점을 제외하거나 보험료에 반영하기에는 검증이 필요합니다. 앱 내부 점수와 보험사의 평가 기준을 구분하고, 데이터 신뢰도와 제휴 조건을 먼저 확인하겠습니다.

장기적으로는 자율주행과 수동 주행이 섞인 상황에서도 운전자의 설명을 차량 기록과 함께 남기는 방안을 검토할 수 있습니다. 현재 구현 범위는 아니며, 책임 판단에 실제로 활용할 수 있는지는 별도 검증이 필요합니다.

### 기록의 보관과 제공

기록은 차량 안에 저장하며 앱이 자동으로 외부에 전송하지 않습니다. 내보내기 기능을 구현하면 운전자가 건별로 선택해 제공하도록 할 계획입니다. 보험 연계도 이용자가 사용 목적과 제공 범위를 확인하고 동의하는 방식을 전제로 검토합니다.

후속 안내는 기록 보관 방법과 제출 절차에 관한 정보 제공을 중심으로 구성합니다. 특정 법률사무소에 사건을 알선하고 수수료를 받는 방식은 사업 범위에 포함하지 않습니다.

### 시연 영상 구성

영상은 평상시 주행, 급제동, 사고 대응, 위협 대응, 고장 대응, 기타 기능 순서로 구성했습니다. 화면 녹화에는 소리가 포함되지 않아 앱의 음성 안내는 “(음성)” 자막으로 표시했습니다.

① 평상시 주행: 대기 화면에서 오늘의 주행, 급제동, 경호 상태와 최근 기록을 확인하고, 기어 D 전환 시 감시가 시작되는 모습을 보여 줍니다.

② 급제동: 주행 중 기록과 안내, 정차 후 원인 선택 과정을 보여 줍니다.

③ 사고 대응: 내비게이션을 전면에 둔 상태에서 에어백 신호를 입력합니다. 앱으로 돌아와 7단계 안내를 진행하고, 주행 요약과 저장된 기록을 확인합니다.

④ 위협 대응: 반복 급제동 후 위협 여부 확인, 문 잠금 요청, 112 연결 안내를 보여 줍니다.

⑤ 고장 대응: 대피 안내와 정차 후 절차를 보여 줍니다.

⑥ 기타 기능: “저장해” 음성 명령을 통한 시각·위치 저장과 주야간 전환을 보여 줍니다.

### 설치와 실행

Pleos Connect 에뮬레이터 v2.1.0(Android 14, API 34)에서 다음 명령으로 설치할 수 있습니다.

adb install -g apk/libetelabs_cardiguard_release.apk

-g 옵션은 설치 시 권한을 함께 허용합니다. Virtual Console에 속도 입력 항목이 없어 에뮬레이터에서는 상단 상태 표시줄 오른쪽의 “시연 모드”로 주행, 급제동, 에어백, 음성 문장을 입력합니다. 시연 모드 버튼은 실제 차량에서는 표시되지 않습니다.
